# DB 詳細設計

- 版: 0.1（AIの下書き）／作成日: 2026-10-01
- DBMS: Supabase PostgreSQL（15 以上）。スキーマ変更は Flyway（`backend/src/main/resources/db/migration`）が正
- 方針（原則）: 事実を正確に記録する（P17）／追記のみ・状態は導出（P18）／関心事ごとにテーブルを分ける（P19, P31）
- 例外: `jobs`・`llm_usage_daily`・`oauth_states` は「予定表・カウンタ・使い捨ての照合値」なので UPDATE / DELETE を許す（ADR-0006）

> 以下の DDL は設計書としての下書き。実装時にマイグレーション `V1__init.sql`〜に分割して置く。

```sql
  id             bigint generated always as identity primary key,
  connection_id  uuid not null references instagram_connections(id),

  message        text not null,
  failed_at      timestamptz not null default now()
);

  connection_id    uuid primary key references instagram_connections(id),
  disconnected_by  uuid not null references members(id),
  disconnected_at  timestamptz not null default now()
);

-- 1団体で未解除の連携は1つだけ（BR-001-02）。新しい連携を記録する API関数は、同じトランザクションで
-- 前の連携の instagram_disconnections を書く。部分一意インデックスは別テーブル参照のため使えないので、
-- 記録は service role の関数 app.record_instagram_connection() に限り、関数内で団体の行をロックして守る。

-- 現在の連携（最新の未解除の連携と、その最新トークンの期限）。暗号文は含めない。
-- トークンの表はクライアントから読めないため、ビューは service role 用（定期処理・API関数）。
-- 画面は下の security definer 関数 public.instagram_connection_status() を使う
create view instagram_connection_current as
select distinct on (c.tenant_id)
       c.id as connection_id, c.tenant_id, c.ig_user_id, c.ig_username, c.connected_at,
       g.expires_at as token_expires_at, g.granted_at as token_granted_at,
       (select max(f.failed_at) from instagram_token_refresh_failures f
         where f.connection_id = c.id and f.failed_at > g.granted_at) as last_refresh_failed_at
from instagram_connections c
join lateral (select expires_at, granted_at from instagram_token_grants
              where connection_id = c.id order by id desc limit 1) g on true
where not exists (select 1 from instagram_disconnections d where d.connection_id = c.id)
order by c.tenant_id, c.connected_at desc;
revoke all on instagram_connection_current from anon, authenticated;

-- 画面用: 自団体の連携状態だけを、暗号文なしで返す（AC-001-03、TOKEN_* 警告）
create function public.instagram_connection_status()
returns table (ig_username text, connected_at timestamptz, token_expires_at timestamptz,
               last_refresh_failed_at timestamptz)
language sql stable security definer set search_path = public, pg_temp as $$
  select v.ig_username, v.connected_at, v.token_expires_at, v.last_refresh_failed_at
    from instagram_connection_current v
   where v.tenant_id = (select tenant_id from app.current_member())
$$;
```

#### 状態遷移の最後の砦（トリガー）

ドメイン（TS / Java の `PostStatus`）が遷移可否を判断し、DB は「`from_status` が現在の状態と一致すること」を確かめる。投稿の行をロックしてから確かめるため、同時の遷移は片方だけ通る（楽観ロックの代わり）。

```sql
-- security definer: クライアントのロールには posts の UPDATE 権限が無いため、行ロックを関数の所有者権限で取る
create function app.check_post_event() returns trigger
language plpgsql security definer set search_path = public, pg_temp as $$
declare current_status text;
begin
  perform 1 from posts where id = new.post_id for update;          -- 同じ投稿の遷移を直列化
  select to_status into current_status from post_events
   where post_id = new.post_id order by id desc limit 1;
  if coalesce(current_status, 'NEW') <> new.from_status then
    raise exception 'post % is %, not %', new.post_id, coalesce(current_status,'NEW'), new.from_status
      using errcode = 'P0409';
  end if;
  return new;
end $$;

create trigger post_events_check before insert on post_events
  for each row execute function app.check_post_event();

-- 追記のみ：UPDATE / DELETE を禁止
create function app.forbid_mutation() returns trigger language plpgsql as $$
begin raise exception '% is append-only', tg_table_name; end $$;
create trigger post_events_append_only before update or delete on post_events
  for each row execute function app.forbid_mutation();
-- 版の固定: 新しい版は投稿が「作成前」か「下書き」のときだけ追加できる（承認待ち以降の内容を変えさせない）
create function app.check_revision_editable() returns trigger
language plpgsql security definer set search_path = public, pg_temp as $$
declare current_status text;
begin
  perform 1 from posts where id = new.post_id for update;
  select to_status into current_status from post_events where post_id = new.post_id order by id desc limit 1;
  if current_status is not null and current_status <> 'DRAFT' then
    raise exception 'post % is %, revisions are frozen', new.post_id, current_status using errcode = 'P0409';
  end if;
  return new;
end $$;
create trigger post_revisions_editable before insert on post_revisions
  for each row execute function app.check_revision_editable();

-- 同じ追記のみトリガーを post_revisions, post_media, post_slides, post_schedules, post_publications,
-- post_failures, member_role_changes, instagram_token_grants, generations, insight_snapshots 等にも付ける
```

#### 投稿の現在（導出ビュー）

```sql
create view post_current with (security_invoker = true) as
select p.id as post_id, p.tenant_id, p.created_by, p.created_at,
       e.to_status as status, e.occurred_at as status_changed_at,
       r.id as revision_id, r.revision_no, r.format, r.media_source, r.caption, r.pr_category, r.genre_id,
       a.revision_id as approved_revision_id,   -- 承認された版（公開されるのはこの版）
       s.scheduled_at,
       pub.ig_media_id, pub.permalink, pub.published_at,
       f.failure_kind as last_failure_kind, f.message as last_failure_message
from posts p
join lateral (select to_status, occurred_at from post_events where post_id = p.id order by id desc limit 1) e on true
join lateral (select * from post_revisions where post_id = p.id order by revision_no desc limit 1) r on true
left join lateral (select revision_id from post_events where post_id = p.id and event_type = 'APPROVED'
                   order by id desc limit 1) a on true
left join lateral (select scheduled_at from post_schedules where post_id = p.id order by id desc limit 1) s on true
left join post_publications pub on pub.post_id = p.id
left join lateral (select failure_kind, message from post_failures where post_id = p.id order by id desc limit 1) f on true;
```

- 予約日時は「最新の確定」。予約取消（SCHEDULE_CANCELLED）後は状態が下書きなので、画面は状態が予約中のときだけ予約日時を出す。
- 「承認された版」は、APPROVED の出来事の `revision_id`。公開ジョブはこの版を公開する（承認後に新しい版を作るには下書きに戻す必要がある）。

```sql
create function app.claim_next_job(p_type text, p_lock interval, p_runner text) returns jobs
language plpgsql as $$
declare j jobs;
begin
  update jobs set status = 'RUNNING', attempts = attempts + 1, locked_until = now() + p_lock
   where id = (select id from jobs
                where status = 'PENDING' and run_at <= now() and job_type = p_type
                order by run_at for update skip locked limit 1)
  returning * into j;
  if j.id is not null then
    insert into job_attempts (job_id, attempt_no, runner) values (j.id, j.attempts, p_runner);
  end if;
  return j;
end $$;
```

## 3. 行レベルセキュリティ（RLS）

すべてのテーブルで `enable row level security`。ポリシーが無いテーブルはクライアントから読めない（service role だけ）。

```sql
-- ログイン中の有効なメンバー
-- security definer の関数はすべて search_path を固定する（関数の乗っ取り対策）
create function app.current_member() returns table (member_id uuid, tenant_id uuid, role text)
language sql stable security definer set search_path = public, pg_temp as $$
  select mc.member_id, mc.tenant_id, mc.role from member_current mc
   where mc.auth_user_id = auth.uid() and mc.active
$$;
create function app.is_member(t uuid) returns boolean
language sql stable security definer set search_path = public, pg_temp as $$
  select exists (select 1 from app.current_member() where tenant_id = t) $$;
create function app.has_role(t uuid, roles text[]) returns boolean
language sql stable security definer set search_path = public, pg_temp as $$
  select exists (select 1 from app.current_member() where tenant_id = t and role = any(roles)) $$;

-- app スキーマは PostgREST（supabase-js の rpc）に公開しない。RLS ポリシーから使えるよう実行権限だけ付ける
grant usage on schema app to authenticated;
grant execute on function app.current_member(), app.is_member(uuid), app.has_role(uuid, text[]) to authenticated;
revoke execute on function app.claim_next_job(text, interval, text), app.try_consume_llm(uuid, text, int)
  from public, anon, authenticated;   -- 定期処理・API関数（service role）だけが呼ぶ
-- 画面から呼ぶ RPC（link_my_member, invite_member, save_post_revision, request_approval, approve_post,
-- request_revision, cancel_schedule, retry_post, return_to_draft, discard_post, decide_pr_submission,
-- instagram_connection_status）は public スキーマに置き、authenticated にだけ execute を付ける

-- 初回ログイン時の結びつけ（Google で確認済みのメールアドレスで照合）
create function public.link_my_member() returns uuid
language plpgsql security definer set search_path = public, pg_temp as $$
declare m uuid;
begin
  select id into m from members
   where email = (auth.jwt() ->> 'email')::citext
     and coalesce((auth.jwt() -> 'user_metadata' ->> 'email_verified')::boolean, false)
     and not exists (select 1 from member_auth_links l where l.member_id = members.id)
     and not exists (select 1 from member_deactivations d where d.member_id = members.id)
   limit 1;
  if m is not null then insert into member_auth_links (member_id, auth_user_id) values (m, auth.uid()); end if;
  return m;
end $$;
```

|---|---|---|---|
| tenants, tenant_settings | メンバー | 管理者（tenant_settings） | なし |
| members, member_role_changes, member_deactivations | メンバー | RPC `invite_member` / `change_member_role` / `deactivate_member` のみ（承認者・管理者。ADMIN の付与・変更・無効化は管理者だけ） | なし |
| member_auth_links | 本人 | RPC `link_my_member` のみ | なし |
| oauth_states, instagram_token_grants, instagram_token_refresh_failures | **なし**（service role のみ） | なし | なし |
| instagram_connections, instagram_disconnections | なし（画面は `instagram_connection_status()` を使う） | 連携は API関数（service role）、解除は管理者の RPC | なし |
| posts, post_origins, post_revisions, post_media, post_slides | メンバー | RPC `save_post_revision` のみ（版の追加は下書きのときだけ。トリガー） | なし |
| post_events | メンバー | **直接の INSERT は不可**。画面の操作は RPC（下表）、定期処理分は service role | なし |
| post_schedules | メンバー | RPC `approve_post` / `retry_post` のみ | なし |
| publish_media, ig_containers, post_publications | メンバー | service role のみ | なし |
| post_failures | メンバー | service role のみ | なし |
| jobs | メンバー（状態の表示用） | service role のみ（tick が予約の確定からジョブを積む） | service role のみ |
| job_attempts, job_attempt_results | 管理者 | service role のみ | なし |
| batch_heartbeats | メンバー | service role のみ | なし |

すべての INSERT ポリシーは `with check (app.is_member(tenant_id))` を含める（子テーブルは親の tenant_id を参照する関数で判定）。

**状態を変える操作はすべて RPC にする**。RPC は security definer で、**出来事の種類ごとのロール**と**対象の版**を確かめてから記録する。業務判断（予約日時の妥当性・画像枚数・文字数など）は画面側のドメインで行い、RPC は**記録・権限・版の整合**だけを担う（判断を DB に重複させない。DB が守るのは遷移表・版の固定・制約）。

| RPC | 出来事 | 許すロール | RPC が確かめること | 同じトランザクションで書くもの |
|---|---|---|---|---|
| `request_approval(post_id, revision_id)` | APPROVAL_REQUESTED | 全ロール | revision_id が最新の版 | post_events |
| `approve_post(post_id, revision_id, scheduled_at)` | APPROVED | 承認者・管理者 | revision_id が直前の APPROVAL_REQUESTED の版と同じ | post_events, post_schedules, generation_feedbacks（版に生成があれば APPROVED。フェーズ2） |
| `request_revision(post_id, instruction)` | REVISION_REQUESTED | 承認者・管理者 | — | post_events（note=指示） |
| `cancel_schedule(post_id)` | SCHEDULE_CANCELLED | 承認者・管理者 | — | post_events |
| `retry_post(post_id, scheduled_at)` | RETRIED | 承認者・管理者 | — | post_events, post_schedules |

- **ジョブは RPC では積まない**（2026-10-02 実装時に変更）。最大試行回数などはジョブ種別（Java のドメイン）が持つため、tick の最初に `JobRepository.enqueueForNewSchedules()` が「予約中で、最新の予約の確定にまだジョブが無い投稿」に公開用画像の準備と公開のジョブを積む。承認から画像の準備までは最大15分遅れるが、公開は予約日時の tick で準備→公開の順に行うので影響しない。
| `return_to_draft(post_id)` / `discard_post(post_id)` | RETURNED_TO_DRAFT / DISCARDED | 承認者・管理者（下書きの破棄は全ロール） | — | post_events |

- 遷移の可否は、`post_status_transitions`（出来事の種類と遷移の組）への外部キーと、現在状態の一致（トリガー）で守る。編集者が APPROVED を名乗って記録することはできない（RPC がロールを確かめ、直接 INSERT は不可）。

| `uploads-private` | 非公開 | `{tenant_id}/posts/{uuid}.jpg`、`{tenant_id}/pr/{uuid}` | メンバー（自団体のパス）、PR入稿は API関数（service role）が受け取った画像を保存 | メンバー（自団体） |
| `media-public` | 公開 | `{tenant_id}/{uuid}.jpg`（UUID v4 で推測不能） | service role（定期処理） | 誰でも（Instagram が取得する） |

- `media-public` の画像は公開から30日後に定期処理（daily）で削除する（Instagram は公開時に取り込むため。要確認）。`publish_media` の記録は残す。
- 無料枠 1GB。1枚 約0.5MB として、下書き画像を含め数千枚で上限に近づく。daily で使用量を確かめ、80%で警告に加える（将来）。

## 5. マイグレーション方針

- Flyway の `V{連番}__{内容}.sql`。追記型（既存マイグレーションを書き換えない）。
- テーブル追加で拡張し、カラム追加は「同じタイミングで記録する事実」の場合だけ（P31）。
- ロールバックは新しいマイグレーションで行う（down は書かない）。
- 外部キーの参照先を先に作る。本書の節の順番は関心事ごとで、作成順ではない。初版の作成順:
