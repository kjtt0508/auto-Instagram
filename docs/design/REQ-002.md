## 2. ドメインモデル

| オブジェクト | 置く業務ロジック | 場所 |
|---|---|---|
| `DraftProposal` | 完全コンストラクタで検証（スライド1〜10、見出し40字・本文200字、キャプション＋ハッシュタグで2,200字・30個、形式と枚数の整合: 画像=1枚／カルーセル=2〜10枚、ニュースなら参照元URL1件以上）。違反の一覧を返す `validate(raw)` | TS（API関数）・Java（一括生成） |
| `GenerationInput` | プロンプトに入れてよい項目だけを持つ（02_外部連携設計 2.3）。入稿者連絡先を持たない | 同上 |
| `PromptVersion` | `render(input)`（Mustache 差し込み）、`purpose.jsonSchema()` | 同上 |
| `LlmUsage` / `LlmQuota` | `nearLimit(used)`（used ≥ 上限×警告割合）。確保は DB の `try_consume_llm`（原子的な加算のため DB に置く。ADR-0006） | TS・Java |
| `Template` | `fill(slide)`：見出し・本文を HTML エスケープして `{{heading}}` `{{body}}` `{{page}}` `{{total}}` に差し込み、`<style>` に CSS を入れた完全な HTML を返す | TS（プレビュー）・Java（画像化） |
| `SlideRole` | 役割ごとのテンプレートの選択（表紙／本文／まとめ） | 同上 |
| `GenerationRoute` | `countsUsage()`（API のみ） | 同上 |
| `GenerationRetryPolicy` | 作り直してよいか（違反があり、まだ1回も作り直していない）、作り直しで渡す違反の説明 | 同上 |

- `Template.fill` は TS と Java の両方にあるため、ADR-0005 の共通テストケース（入力スライド → 期待 HTML）で一致を確かめる。
- テンプレートのフォントは `templates/fonts/`（Noto Sans JP など、ライセンス確認済みのもの）に置き、画面のプレビューと Playwright の両方から同じファイルを読む（見た目の差を防ぐ）。

## 3. 画面

| 画面（タスク） | 利用者の関心事 | 表示するドメインオブジェクト | 項目の並び・グルーピング | 状態ごとの見せ方 |
|---|---|---|---|---|
| S-07 AIで下書きを作る | 案を作り、直し、採用する | DraftProposal, Generation, LlmUsage | ①元ネタ（または自由入力）②「生成」③スライドのプレビュー（横スワイプ）＋キャプション ④修正指示の入力欄と「作り直す」⑤「この案で投稿を作る」 | 生成中はスケルトン表示（最大60秒）。上限が近い→黄色の注記、到達・障害→「手動コピペで続ける」ボタンを主ボタンにする |
| S-07 手動コピペ | 外部AIで続ける | — | ①プロンプト（コピーボタン）②JSON 貼り付け欄 ③「取り込む」 | 違反は `details` を行ごとに表示（AC-002-07） |
| S-09 テンプレート管理 | トンマナを整える | Template | 左: HTML/CSS エディタ（スマホでは上下）／右: サンプルスライドでのプレビュー | 保存すると新しい版。公開済み投稿は作成時の版のまま |
| S-10 プロンプト管理・生成ログ | 品質を改善する | PromptVersion, Generation | 用途タブ（企画・キャプション・修正）→ 版の一覧（有効の版に印）→ 本文／生成ログ（日時・経路・結果・採用されたか・修正指示） | — |

- プレビューは `<iframe sandbox srcdoc="...">`（`allow-scripts` を付けない）で、`Template.fill` の結果を 1080×1350 を縮小表示する。
- 下書き案を取り込むと、投稿の版は `media_source=TEMPLATE`、スライドは `post_slides` に、`generation_id` 付きで保存し、`generation_feedbacks(ADOPTED)` を記録する。

## 4. 外部との契約

- Gemini: `02_外部連携設計.md` 2章
- API関数: `POST /api/generations`、`/api/generations/manual-prompt`、`/api/generations/manual`（同 5章）

`POST /api/generations` の処理（API関数）:

```text
member = 認証（JWT → member_current）
input  = GenerationInput.from(idea, examples=[], genres, ngExpressions, today, previous?, instruction?)
prompt = 有効な PromptVersion(purpose)
settings = tenant_settings_current
(allowed, used) = try_consume_llm(tenant, settings.model, settings.limit)
if !allowed → generations(QUOTA_EXCEEDED) を記録して 409
raw = Gemini.generate(prompt.render(input), purpose.jsonSchema(), settings.model)   # 60秒
result = DraftProposal.validate(raw)
policy = GenerationRetryPolicy（ドメイン）: policy.allowsRetry(result) なら policy.feedback(result) を添えて作り直す（利用回数をもう1回確保）
generations を記録（SUCCEEDED / INVALID_OUTPUT / LLM_ERROR）
return { generationId, proposal, usage: { used, limit, nearLimit } }
```

- Cloudflare 無料枠の CPU 時間上限（10ms）は「待ち時間」を含まない。JSON の検証は小さいので収まる見込み（要確認：フェーズ0で計測。超えるなら ADR-0002 の見直し）。
- 画面は API の応答を待つ間、ほかの操作を止めない。

## 5. 永続化

| 保存先 | 記録する事実 | タイミング | 欠損を許す項目と理由 |
|---|---|---|---|
| generations | 生成1回 | 生成のたび（失敗も） | llm_model（手動）、output（失敗）、parent/instruction（修正以外）、idea_id、requested_by（一括）、latency_ms（手動） |
| generation_feedbacks | 採用・修正・承認・破棄 | 画面の操作時。承認は REQ-001 の APPROVED と同じトランザクションで、その版の generation に `APPROVED` | なし |
| prompt_versions / prompt_activations | 版と有効化 | 管理者の保存・有効化 | なし |
| template_versions | テンプレートの版 | 保存 | なし |
| post_slides | 版のスライド | 取り込み・編集 | なし |
| publish_media | 画像化した JPEG | tick | なし |
| llm_usage_daily | 日次回数 | 生成の直前 | なし |

- 生成ログは品質改善と分析の元データなので削除しない。ただし `input` に個人情報が入らないことを型で保証する（`GenerationInput`）。
- 有効なプロンプト版 = 用途ごとに `prompt_activations` の最新。

## 6. 画像化（PREPARE_MEDIA の TEMPLATE）

```text
MediaPreparation（TEMPLATE）:
  revision = 承認された版（post_slides と template_version）
  browser = Playwright.chromium（tick 内で1回だけ起動し使い回す）
  for slide in revision.slides:
    html = template.fill(slide, page, total)
    page.setViewportSize(width, height); page.setContent(html, waitUntil=networkidle)
    page.evaluate("document.fonts.ready")
    bytes = page.screenshot(type=JPEG, quality=90, fullPage=false)
    ImageSpec.check(bytes, width, height)  → media-public へアップロード → publish_media
```

- 外部リソースの読み込みは禁止（`page.route("**", abort unless file:// か data:)`）。フォントはローカルファイルを `file://` で読む。
- 画像化した JPEG が仕様違反になった場合は MEDIA_REJECTED として投稿を失敗にする（テンプレートの不備を人に知らせる）。

## 7. 異常系・外部依存の縮退

| 事象 | 振る舞い | 受入基準 |
|---|---|---|
| 差し込み文言に HTML/スクリプト | エスケープして文字として表示。プレビューは sandbox、画像化は外部通信を遮断 | AC-002-01 |
| Gemini がスキーマ違反を2回 | INVALID_OUTPUT を記録し、手動コピペを案内 | AC-002-04 |
| 生成上限の8割 / 到達 | 警告（LLM_LIMIT_NEAR）/ 呼ばずに 409、警告（LLM_LIMIT_REACHED） | AC-002-06 |
| Gemini 429 / 5xx / タイムアウト | 429 は即 409 扱い、5xx は1回再試行、60秒でタイムアウト（504） | — |
| 手動コピペの JSON 不正 | 違反箇所を表示、利用回数は増えない | AC-002-07 |
| モデル名の変更 | 設定の新しい版で切り替え。利用回数はモデル別 | AC-002-10 |
| Playwright の起動失敗 | ジョブを RETRY（次の tick）。3回失敗で投稿を失敗（UNKNOWN） | — |

## 9. 決定事項（ADR）

- ADR-0005 二重実装（Template.fill、DraftProposal）の揃え方
- ADR-0006 llm_usage_daily のカウンタは UPDATE を許す
