## 3. 処理の詳細

### 3.1 インサイト収集

```text
対象 = 公開済み かつ published_at >= 今日-30日 かつ 今日のスナップショットが無い投稿
for post in 対象:
  try: metrics = Instagram.insights(post.igMediaId)  → insight_snapshots に INSERT（主キー重複は無視）
  catch TOKEN_INVALID: 以降を中止（連携切れ。警告で知らせる）
  catch その他: ログ（ID と区分のみ）して次へ
```

### 3.2 ニュース収集

`02_外部連携設計.md` 3章。新着1件ごとに: `news_items` 記録 → 事実の抜き出し（Gemini、LLM 利用回数を確保。上限なら翌日に回す）→ `ideas`（出どころ=ニュース、参照元URL）。

### 3.3 週次分析（Python, pandas）

- 入力: 直近90日の公開済み投稿（`post_current`）と `insight_snapshots`（各投稿の公開7日後時点、無ければ最新）
- 出力（`insight_reports.report` の JSON）:

```json
{
  "period": { "from": "2027-01-01", "to": "2027-03-31" },
  "byGenre":    [{ "genre": "イベント", "posts": 12, "medianReach": 850, "medianSaveRate": 0.061, "medianShareRate": 0.012 }],
  "byFormat":   [{ "format": "CAROUSEL", "posts": 20, "medianReach": 900, "medianSaveRate": 0.07 }],
  "byTimeSlot": [{ "slot": "18-21", "posts": 15, "medianReach": 1020 }],
  "standout":   [{ "postId": "...", "saveRate": 0.12, "permalink": "..." }],
  "effect":     { "postsPerWeek": 4.5, "baselinePostsPerWeek": null }
}
```

- reach=0 の投稿は比率の計算から除く（AC-004-06）。件数が3件未満の区分は「参考値」として印を付ける。
- 導入効果（作業時間・投稿数・反応）は、フェーズ0のベースライン計測（要確認）を手入力の記録（`tenant_baselines` テーブル。計測項目が決まってから設計する）として持ち、比較を表示する。作業時間は自動では測れないため、導入後も月1回の聞き取りで記録する。

## 5. 永続化

| 保存先 | 記録する事実 | タイミング | 欠損を許す項目と理由 |

## 6. 異常系

| 事象 | 振る舞い | 受入基準 |
|---|---|---|
| 既にネタ化した URL | 一意制約でスキップ | AC-004-01 |
| ソースの 500 / タイムアウト | そのソースだけ失敗を記録して続行 | AC-004-02 |
| 同じ日の再実行 | 主キーで重複しない | AC-004-03 |
| 公開31日目 | 対象外 | AC-004-04 |
| reach=0 | 比率から除外 | AC-004-06 |
| robots.txt で拒否 | 取得しない（失敗として記録） | NFR-004-01 |
