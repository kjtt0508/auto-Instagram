## 2. ドメインモデル

| オブジェクト | 置く業務ロジック |
|---|---|
| `Idea` | 本文1〜2,000字、出どころがニュースなら参照元URL必須、`use(post)`・`skip()` |
| `IdeaSource` | `initialPrCategory()`（PR入稿→PR）、`requiresSourceUrl()`（ニュース）、`prCategoryLocked()`（PR入稿→通常へ変更不可） |
| `StandoutPost` | 公開済み・直近90日・公開7日後時点のインサイトで `saved / reach` の上位N（reach=0 を除く）。フェーズ4までインサイトが無い間は空（例なしで生成） |
| `AutoCheck` | 下の検査を順に適用し `CheckFinding` の一覧を返す。各検査は小さなルールオブジェクト（`PrSuspicionRule`, `DateWeekdayRule`, `PersonalNameRule`, `NgExpressionRule`, `ImageSpecRule`, `SourceUrlRule`） |
| `CheckKind` | `severity()`（IMAGE_SPEC のみエラー） |
| `Post` | `requestApproval(findings)`: エラーの指摘があれば拒否。`requestRevision(instruction)`: 承認待ち→下書き |
| `PrSubmission` | 文面1〜2,000字、画像0〜10枚、`accept(by)` → `Idea`（出どころ=PR）を作る、`reject(by, note)` |
| `SubmitterContact` | メール形式。`GenerationInput` には渡せない（型に無い） |

### 自動チェックの規則

| チェック項目 | 判定 | 重要度 |
|---|---|---|
| PR_SUSPECTED | PR区分=通常で、キャプション・スライドに「提供」「協賛」「PR」「タイアップ」「スポンサー」（団体設定で追加可）を含む | 注意 |
| DATE_WEEKDAY_MISMATCH | `M月D日（曜）`・`M/D(曜)` の形を抽出し、年は「今日以降で最も近いその日付」として曜日を計算して一致しなければ指摘 | 注意 |
| PERSONAL_NAME | 「〇〇さん」「〇〇くん」「〇〇氏」の直前の語、および団体設定の除外語にない人名らしい語（フェーズ3は単純な正規表現。精度が足りなければ LLM 判定を検討。要確認） | 注意 |
| NG_EXPRESSION | 団体の NG 表現（削除されていないもの）を含む | 注意 |
| IMAGE_SPEC | `ImageSpec` 違反、枚数違反 | エラー |
| SOURCE_URL_MISSING | 元ネタがニュースなのに、キャプションか生成の参照元URLが無い | 注意 |

AC-003-05 の例: 「11月3日（火）」で、対象の年の11/3が月曜 → 「日付と曜日が合っていません（11月3日は月曜日）」。

| 画面（タスク） | 利用者の関心事 | 表示するドメインオブジェクト | 項目の並び・グルーピング | 状態ごとの見せ方 |
|---|---|---|---|---|
| S-06 ネタ箱 | 一言入れる、使えるネタを探す | Idea | 上: 入力欄（1行、送信ボタン）／下: タブ「未使用 / 使用済み / 見送り」、各ネタに出どころのバッジ（メモ・ニュース・PR） | ニュースは参照元リンク、PRは団体名と希望日。各ネタに「AIで企画」「見送る」 |

| P-01 PR入稿フォーム（公開） | 掲載を依頼する | — | 団体名、文面、画像（10枚まで）、希望日、担当者名、メール、同意事項（掲載は確約しない・個人情報の扱い）、Turnstile、送信 | 送信後「受け付けました。掲載の可否は運営からご連絡します」 |

- P-01 の同意文・個人情報の扱いの文言は **AIの下書き。専門家の確認が必要**（管理部と確認）。

## 4. 外部との契約

- `POST /api/pr-submissions`（02_外部連携設計 5章）。処理:

```text
turnstile.verify(token, ip) → 失敗なら 400 BOT_CHECK_FAILED
ipHash = HMAC(ip); 直近1時間の同じ ipHash の件数 ≥ 5 → 429
PrSubmission.create(orgName, body, desiredDate, images) / SubmitterContact.create(name, email)（境界で検証）
画像: 1枚8MB・合計40MB・JPEG/PNG のみ（マジックバイトで判定）→ uploads-private/{tenant}/pr/{uuid}
pr_submissions, pr_submission_contacts(delete_after = 今日+180日の仮置き), pr_submission_media を1トランザクションで記録
201
```

- 採否は RPC `decide_pr_submission(submission_id, decision, note)`: 採否の記録＋採用時は `ideas`（出どころ=PR、本文=文面、団体名・希望日を本文の先頭に整形）を作る。連絡先の `delete_after` を「採否決定日+180日」に置き換える（このテーブルは削除期限の更新を許す。ADR-0006）。

## 5. 永続化

| 保存先 | 記録する事実 | タイミング | 欠損を許す項目と理由 |
|---|---|---|---|
| ideas | ネタ | 投入・採用・収集 | source_url（メモ・PR）、news_item_id / pr_submission_id（出どころ次第。CHECK で整合）、created_by（定期処理） |
| idea_dispositions | 使った／見送った | 取り込み・見送り | decided_by（一括生成） |
| post_origins | 投稿の元ネタ | 取り込み | なし |
| pr_submissions / _media / _contacts / _decisions | 入稿・添付・連絡先・採否 | 入稿・採否 | desired_date（希望なし）、note |
| ng_expressions / _removals | NG 表現の登録・削除 | 設定 | なし |
| post_events(REVISION_REQUESTED) | 修正指示 | 承認者の操作 | note に指示を入れる |

- 自動チェックの結果は保存しない（その時点の内容から毎回導出できる。承認の記録には、承認時の指摘件数を `post_events.note` に要約して残す）。
- 入稿者連絡先は daily で `delete_after < 今日` を物理削除（個人情報を長く持たない）。

## 6. 異常系

| 事象 | 振る舞い | 受入基準 |
|---|---|---|
| ネタが空・長すぎる | 登録しない | AC-003-02 |
| 伸びた投稿がまだ無い | 例なしで生成 | AC-003-03 |
| PR の可能性・曜日の矛盾・NG 表現 | 注意を出す（承認は可能） | AC-003-04〜06 |
| 修正指示で再生成が失敗（上限・障害） | 投稿は下書きに戻ったまま。手動コピペを案内 | AC-003-07 |
| Turnstile 失敗 | 何も保存しない | AC-003-09 |
| 同一IPの連続入稿 | 429 | AC-003-12 |
| 編集者が連絡先を見ようとする | RLS で取得できない | AC-003-10 |
| PR区分を通常に変えようとする（PR入稿由来） | 画面で選べない。保存時も `IdeaSource.prCategoryLocked()` で拒否 | AC-003-11 |
