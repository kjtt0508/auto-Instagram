# ADR-0007: Instagram のアクセストークンはアプリで AES-256-GCM 暗号化して保存する

- 状態: 提案
- 日付: 2026-10-01
- 関連: REQ-001（BR-001-02, NFR-001-03）

## 背景
要件6章「アクセストークンは暗号化してDBに保存」。トークンを書くのは API関数（OAuth 完了時、TS）と定期処理（更新時、Java）、読むのは定期処理。

## 決定
- AES-256-GCM（12バイトの乱数 IV、認証タグ込みの暗号文）。鍵は `TOKEN_ENC_KEY_V{n}`（32バイト）を Cloudflare Secret と GitHub Secrets に置く。
- 保存時に `key_version` を記録し、鍵の切り替えは新しい鍵で次の更新から暗号化する（古い鍵は全トークンが更新されるまで残す）。
- 追加認証データ（AAD）に `connection_id` を入れ、別の連携の暗号文に差し替えられても復号できないようにする。
- `instagram_token_grants` は RLS のポリシーを付けず、クライアントからは読めない（service role のみ）。
- 暗号化・復号は TS（Web Crypto）と Java（`javax.crypto`）で実装し、共通のテストベクタ（ADR-0005 の fixtures）で互換を確かめる。

## 検討した代替案
- Supabase Vault: DB 内で暗号化できるが、復号を DB 関数経由にする必要があり、Java/TS 両方からの扱いと鍵の所在が分かりにくい。将来の移行先として残す。
- 暗号化しない（RLS だけ）: 要件を満たさない。DB のダンプが漏れたときに守れない。

## 結果
- 鍵を2か所（Cloudflare と GitHub）に置く運用になる。鍵はパスワード管理ツールで管理し、ファイルに書かない。
