# ADR-0001: 定期処理は GitHub Actions の cron で動かし、リポジトリは公開にする

- 状態: 承認（2026-10-01 梶原。リポジトリは公開）
- 日付: 2026-10-01
- 関連: REQ-001（BR-001-08, NFR-001-01）/ 原則 P33

## 背景
月額0円が前提で、常駐サーバーを持てない。予約投稿には15分程度の間隔で動く定期処理が必要。
要件定義書7章で GitHub Actions の cron＋Java バッチが選ばれている。

## 決定
- tick（15分ごと）、daily、weekly の3つのワークフローで動かす。
- リポジトリは**公開**にする。非公開だと無料枠（2,000分/月）を tick だけで超える（基本設計 6.1）。
- 公開に伴い、秘密情報は GitHub Secrets のみ、ログには ID・件数・区分しか出さない。Actions のアーティファクトは使わない。

## 検討した代替案
- 非公開＋tick を30分間隔・日中のみ: 上限ぎりぎりで余裕がなく、遅延も増える。
- Supabase の pg_cron＋Edge Functions: Playwright（画像化）が動かせない。Java バッチの要件とも合わない。
- Cloudflare Workers の Cron Triggers: 同上（ブラウザが動かせない。無料枠では Browser Rendering の制約が大きい）。

## 結果
- cron の遅れ（数分〜数十分）を受け入れる。公開猶予（6時間）で人に判断を戻す。
- 60日間更新のない公開リポジトリは cron が止まりうるため、月1回の再有効化と BATCH_STOPPED 警告で対処する。
- ソースコードが公開される。京愛の実績として見せられる利点がある一方、新島info固有の情報（テンプレートの文言、プロンプト）は DB に置き、リポジトリには入れない。
- 公開リポジトリに決定（2026-10-01）。将来非公開に変える場合はこの ADR を置き換える。
