# ADR-0010: テンプレートはリポジトリのファイルで版を管理し、差し込みはテンプレート内のスクリプトが行う

- 状態: 承認（2026-10-05 梶原）。同日、設計レビューを受けて「決定 3・4」に安全性と描画の一致の具体を書き足した（方針は変えていない）
- 日付: 2026-10-05
- 関連: REQ-002（BR-002-01, 02, NFR-002-04, 05）、ADR-0005 / 原則 P03 P20

## 背景
REQ-002 の画像は、AI が作った文言をテンプレート（HTML/CSS）に差し込んで描く。描く場所は2つある。
画面のプレビュー（ブラウザ、TS）と、承認後の画像化（定期処理、Java＋Playwright）。旧設計は次の形だった。
- テンプレートの HTML/CSS を DB（template_versions）に保存し、管理者が画面で編集する
- 差し込み（`Template.fill`）を TS と Java に二重実装し、共通テストケースで揃える

REQ-002 の具体化（2026-10-04）で「テンプレートのデザインを画面から編集すること」は対象外になった。
また、プレビューと画像化で文字の位置・折り返しが一致すること（NFR-002-04）が求められる。

## 決定
1. テンプレートは `templates/<名前>@<版>/`（HTML・CSS・描画スクリプト）としてリポジトリに置く。版は変更しない（変えるときは新しい版のフォルダを作る。既存の版のファイルのハッシュをテストで固定する）。
2. 差し込みはテンプレートの中の描画スクリプトが行う。スライドの中身・投稿の型の設定・画像（data URL）を JSON で受け取り、文言は `textContent` で入れる（HTML として解釈しない）。TS と Java は JSON を渡すだけで、差し込みの実装は1つ。
3. プレビューは `<iframe sandbox="allow-scripts" src="/templates/<版>/index.html">`（`allow-same-origin` なし＝opaque origin）、画像化は Playwright で、同じファイルを描く。
   - データは `postMessage` で渡し、テンプレートは `event.source === window.parent` を確かめる。srcdoc に JSON を埋め込まない（`</script>` で抜け出せるため）。
   - テンプレートは CSP（`default-src 'none'` に自分のスクリプト・スタイル・フォントと data:/blob: の画像だけを許す）を持つ。画像は data URL / blob で渡す。
   - opaque origin からフォントを読むため、`/templates/*` に `Access-Control-Allow-Origin: *` を付ける。
   - Playwright は `page.route` で架空の origin（`https://template.local/<版>/`）にテンプレートのファイルを配り、それ以外の通信はすべて遮断して `navigate` する（`file://` を広く許さない）。
   - `render(data)` は、フォントと全画像の decode を待つ Promise を返す。
4. フォントは OFL の Noto Sans JP と Noto Color Emoji を `templates/<版>/fonts/` に置く（ライセンス文も置く）。フォントも版のハッシュ固定の対象にする。プレビュー（iOS は WebKit）と画像化（Chromium）の一致は、Playwright の webkit と chromium で同じデータを描いて許容差つきで比べて確かめる（NFR-002-04）。
5. 団体の素材（ロゴ）は公開リポジトリに置かず、Storage に置いて投稿の型の設定から参照する。
6. 投稿の版は、使ったテンプレートの版の名前（例 `niijima@1`）を記録する。

## 理由
- 差し込みを1つにすると、TS と Java の結果がずれる余地が無い（P03。ADR-0005 の二重実装を1つ減らす）。
- ファイルと Git で版を管理すると、レビュー・差分・巻き戻しが通常のコードと同じにできる。編集画面を作らなくてよい。
- `textContent` での差し込みは、文言に HTML が混ざっても文字として描く（AC-002-01）。
- 公開リポジトリにロゴを置かないことで、新島info の素材を公開しない（リポジトリ公開の方針）。

## 却下した案
- DB に HTML を持ち画面で編集する: 要件の対象外。XSS の面が増え、版のレビューもしにくい。
- 差し込みを TS・Java に二重実装: 文字の扱い（エスケープ・強調する語の分割）がずれうる。
- サーバー側で SVG を組み立てる（satori 等）: 画面のプレビューと別の描画系になり、NFR-002-04 を満たしにくい。

## 影響
- 旧設計の `templates` / `template_versions` テーブルと S-09 テンプレート管理は作らない。
- テンプレートを変えるにはコードの変更とデプロイが要る（京愛が行う）。
- 画面のビルドで `templates/` を静的出力にコピーする。
