# 本番環境の準備（フェーズ1）

REQ-001（予約投稿の土台）を、実際の Supabase・Google・Instagram・Cloudflare・GitHub につないで動かすまでの手順。
上から順に進める。各サービスの画面の名前は 2026-10 時点の想定で、変わっていることがある（**要確認** と書いた所は特に）。

- 秘密情報（キー・パスワード・暗号鍵）は**パスワード管理ツールにだけ**保存する。このリポジトリ・チャット・メールに書かない（公開リポジトリ。ADR-0001）
- 費用は0円の設定にする。どのサービスでも**課金・有料プランを有効にしない**（NFR-001-01）

## 0. 先に決めておくこと

| 項目 | 例 | 使う所 |
|---|---|---|
| 管理画面の URL | `https://niijima-ig.pages.dev`（Cloudflare Pages のプロジェクト名で決まる） | Supabase・Google・Meta のリダイレクト先 |
| 最初の管理者の Google アカウント | 京愛の担当者のアドレス | 初期データ（5章） |
| 最初に連携する Instagram アカウント | まず京愛のテスト用ビジネスアカウント、確認後に新島info | Meta のテスター（6章） |

以下、管理画面の URL を `<ADMIN_URL>`、Supabase のプロジェクト ID を `<ref>` と書く。

## 1. Supabase

1. https://supabase.com で新しいプロジェクトを作る。リージョンは東京（Northeast Asia (Tokyo)）、プランは Free。DB のパスワードはパスワード管理ツールに保存する
2. **Project Settings → API**（要確認: 「API Keys」）で次を控える
   - Project URL（`https://<ref>.supabase.co`）→ `SUPABASE_URL`
   - anon（公開してよいキー）→ `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - service_role（**秘密**。RLS を通らない）→ `SUPABASE_SERVICE_ROLE_KEY`
3. **Connect → Session pooler**（IPv4 で届く接続先。GitHub Actions から使う）で接続文字列を控え、JDBC の形に直す
   - `SUPABASE_DB_URL` = `jdbc:postgresql://aws-0-ap-northeast-1.pooler.supabase.com:5432/postgres`（ホスト名は画面の表示どおり）
   - `SUPABASE_DB_USER` = `postgres.<ref>`
   - `SUPABASE_DB_PASSWORD` = 1. のパスワード
4. **Authentication → URL Configuration**
   - Site URL: `<ADMIN_URL>`
   - Redirect URLs に `<ADMIN_URL>/**` と、手元で開発するなら `http://localhost:3000/**` を足す
5. **Authentication → Sign In / Providers → Google** を有効にし、2章で作るクライアント ID とシークレットを入れる（2章のあとで戻ってくる）
6. メールでの新規登録は使わないので、**Email** のサインアップは無効にしておく（許可リストにない人はどのみち何も読めないが、不要な入口を閉じる）

## 2. Google Cloud（Google ログイン）

1. https://console.cloud.google.com でプロジェクトを作る
2. **Google Auth Platform（OAuth 同意画面）** を「外部」で作る。アプリ名「新島info 投稿」、サポートメールを入れる。スコープは既定（email・profile・openid）だけでよい
3. 公開ステータスを「本番環境」にする（「テスト」のままだと、登録したテストユーザー以外はログインできない。email・profile だけなら審査は不要。**要確認**）
4. **クライアント → クライアントを作成**（ウェブアプリケーション）
   - 承認済みのリダイレクト URI: `https://<ref>.supabase.co/auth/v1/callback`
5. 表示されたクライアント ID とシークレットを、1章 5. の Supabase の Google 設定に入れる

## 3. トークン暗号鍵

Instagram のアクセストークンを暗号化する鍵（32バイト、base64。ADR-0007）。**一度決めたら変えない**（変えると保存済みのトークンが読めなくなる）。

```sh
openssl rand -base64 32
# openssl が無ければ: python -c "import os,base64;print(base64.b64encode(os.urandom(32)).decode())"
```

出てきた値をパスワード管理ツールに `TOKEN_ENC_KEY_V1` として保存し、GitHub（4章）と Cloudflare（7章）の**両方に同じ値**を入れる。

## 4. GitHub（定期処理とマイグレーション）

リポジトリ https://github.com/kjtt0508/auto-Instagram の **Settings** で設定する。

1. **Secrets and variables → Actions → Secrets** に登録

   | 名前 | 値 |
   |---|---|
   | `SUPABASE_DB_URL` | 1章 3. の JDBC の URL |
   | `SUPABASE_DB_USER` | `postgres.<ref>` |
   | `SUPABASE_DB_PASSWORD` | DB のパスワード |
   | `SUPABASE_URL` | `https://<ref>.supabase.co` |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role キー |
   | `TOKEN_ENC_KEY_V1` | 3章の鍵 |

2. （任意）**Variables** に `IG_API_VERSION`（例 `v23.0`。未設定なら v23.0。着手時の最新を **要確認**）
3. **Environments → New environment** で `production` を作り、**Required reviewers** に自分を入れる（マイグレーションを流す前に承認が要るようにする）
4. **Settings → Notifications**（個人設定）で、Actions の失敗メールが届くことを確認する（トークン更新の失敗はメールで気づく。BR-001-11）

## 5. DB を作る（マイグレーションと初期データ）

1. **Actions → migrate → Run workflow**（main）を実行し、承認する。V1〜V7 が流れ、テーブル・RLS・RPC・Storage のバケットができる
   - 終わったら Supabase の **Storage** に `uploads-private`（非公開）と `media-public`（公開）があることを確かめる
2. 初期データ（団体・最初の管理者・設定）を入れる。手元に `psql` がある場合:

   ```sh
   # 接続文字列は Supabase の Connect → Session pooler の「URI」（postgresql://… の形）
   psql "postgresql://postgres.<ref>:<DBパスワード>@aws-0-ap-northeast-1.pooler.supabase.com:5432/postgres" \
     -v tenant_name='新島info' -v admin_email='<管理者のGoogleアドレス>' -v admin_name='<表示名>' \
     -f scripts/seed_tenant.sql
   ```

   `psql` が無い場合は、Supabase の **SQL Editor** に `scripts/seed_tenant.sql` の `insert … with` の部分を貼り、`:'tenant_name'` などを実際の値（`'新島info'` など）に置き換えて実行する。

## 6. Meta（Instagram ログイン方式のアプリ。ADR-0003）

1. 連携する Instagram アカウントを**ビジネス**または**クリエイター**にしておく（Instagram アプリの設定 → アカウントの種類。新島infoの切り替えは新島info側の合意が要る。REQ-001 assumptions）
2. https://developers.facebook.com でアプリを作る。用途は「Instagram の API」→「Instagram ログインによる API の設定」（**要確認**: 画面の名前）
3. アプリは**開発モードのまま**にする（App Review を受けない。要件2章）
4. **アプリの役割 → Instagram テスター** に連携するアカウントを追加し、そのアカウントで招待を承認する（Instagram の設定 → アプリとウェブサイト → テスターへの招待。**要確認**）
5. **Instagram ログインによるビジネスログイン** の設定で、OAuth リダイレクト URI に `<ADMIN_URL>/api/instagram/callback` を登録する
6. Instagram アプリ ID と Instagram アプリシークレット（Facebook のアプリ ID とは**別の値**）を控える

## 7. Cloudflare Pages（管理画面と API関数）

1. https://dash.cloudflare.com → **Workers & Pages → 作成 → Pages → Git に接続** で、このリポジトリを選ぶ
2. ビルドの設定

   | 項目 | 値 |
   |---|---|
   | 本番ブランチ | `main` |
   | ルートディレクトリ | `frontend` |
   | フレームワーク | なし（None） |
   | ビルドコマンド | `npm run build` |
   | 出力ディレクトリ | `out` |

3. **環境変数（ビルド時に画面へ埋め込む。公開してよい値だけ）**
   - `NEXT_PUBLIC_SUPABASE_URL` = `https://<ref>.supabase.co`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` = anon キー
   - `NODE_VERSION` = `22`
4. **シークレット（API関数だけが使う。「暗号化」を選ぶ）**

   | 名前 | 値 |
   |---|---|
   | `SUPABASE_URL` | `https://<ref>.supabase.co` |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role キー |
   | `TOKEN_ENC_KEY_V1` | 3章の鍵（GitHub と同じ値） |
   | `IG_APP_ID` | 6章 6. の Instagram アプリ ID |
   | `IG_APP_SECRET` | 6章 6. の Instagram アプリシークレット |
   | `IG_REDIRECT_URI` | `<ADMIN_URL>/api/instagram/callback`（6章 5. と**完全に同じ**文字列） |
   | `IG_API_VERSION` | 例 `v23.0` |

5. デプロイし、`<ADMIN_URL>` が開けることを確かめる。プロジェクト名で URL が 0章と変わったら、Supabase（1章 4.）と Meta（6章 5.）・`IG_REDIRECT_URI` を合わせて直す

## 8. 動作の確認

上から順に確かめる。問題があれば止めて、9章を見る。

| # | 操作 | 期待すること |
|---|---|---|
| 1 | `<ADMIN_URL>` を開き、5章の管理者のアカウントで Google ログイン | ホームが開く。警告に「Instagramと連携していません」「定期処理が止まっています」が出る（この時点では正しい） |
| 2 | 許可リストに無い Google アカウントでログイン | 「利用が許可されていません」（AC-001-01） |
| 3 | 設定 → Instagramと連携 → Instagram で許可 | 設定画面に戻り、`@アカウント名` と有効期限（約60日後）が出る（AC-001-03） |
| 4 | 定期処理を再開する: `gh workflow enable tick.yml` と `gh workflow enable daily.yml`（または Actions の画面で Enable workflow）。続けて tick を **Run workflow** で1回手動実行 | 実行が成功し、ホームの「定期処理が止まっています」が消える |
| 5 | 新規投稿で画像1枚とキャプションを入れ「承認を依頼」→ 投稿詳細で公開日時を**20分後**にして「承認して予約」 | 状態が「予約中」になる |
| 6 | 予約時刻から15分ほど待つ（tick は15分ごと。GitHub の混雑でさらに遅れることがある） | 状態が「公開済み」になり、「Instagramで見る」で投稿が開ける（AC-001-12） |
| 7 | daily を **Run workflow** で手動実行 | 成功する（期限まで30日以上あるので、トークンは更新しない） |

確認できたら、テスト用の投稿は Instagram 側で削除してよい（システムは公開後の編集・削除を扱わない）。
これでフェーズ0の「Meta 開発者アプリでのテスト投稿」も確認できたことになる。

## 9. うまくいかないとき

| 症状 | まず見る所 |
|---|---|
| ログイン後に「利用が許可されていません」 | 5章 2. のメールアドレスと、ログインした Google アカウントが一致しているか（大文字小文字は区別しない） |
| Google ログインで redirect_uri_mismatch | 2章 4. のリダイレクト URI が `https://<ref>.supabase.co/auth/v1/callback` か |
| ログイン後に Supabase のエラー画面・別の URL に飛ぶ | 1章 4. の Site URL と Redirect URLs |
| 連携で「連携の有効期限が切れました」 | Instagram の許可画面で10分以上たった。もう一度連携する |
| 連携で「ビジネスまたはクリエイターの…」 | 6章 1. のアカウントの種類 |
| 連携で「連携に失敗しました」 | Cloudflare の **Functions のログ**（`[api] instagram/callback: …` の行。状態コードだけが出る）。`IG_REDIRECT_URI` と Meta の登録の不一致が多い |
| migrate・tick が失敗 | Actions のログの最初のエラー。DB に届かないなら 1章 3. の Session pooler の URL・ユーザー名（`postgres.<ref>`） |
| 公開されずに「失敗（連携切れ）」 | 設定画面で連携し直してから、ホームで再実行（AC-001-17, 18） |
| 「定期処理が止まっています」が消えない | 管理画面の「定期処理が止まっているとき」の手順（`/runbook/`） |

## 付録: 手元で画面を開発するとき

`frontend/.env.local`（コミットしない。`.gitignore` 済み）に次を書いて `npm run dev`:

```
NEXT_PUBLIC_SUPABASE_URL=https://<ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon キー>
```

API関数（Instagram 連携）を手元で動かすときは、`frontend/.dev.vars` に 7章 4. の値を書き、`npm run build` のあと `npx wrangler pages dev out` で開く。
