# v0.3.0（2026-10-09）

## 業務上の変更（ドメインの言葉で）
- REQ-002: AIで下書き（画像・キャプション）を生成する
  - ネタ（箇条書き）から、新島info の投稿の型（表紙 → 中のスライド → 最後のスライド）に沿った下書き案を AI が作る。画像の中の文字は AI が文言だけを作り、テンプレート `niijima@1` が描く（ADR-0010）
  - 表紙の文言（対象・キーワード12文字まで・添え書き・締めの言葉・帯の色）、中のスライドの文言（見出し・説明文・強調する語）、キャプション本文と追加のハッシュタグを、人がその場で直せる。保存と承認の依頼の前に、AI と同じ文字数の検査をかける
  - 修正指示で文言だけを作り直す（素材画像・背景写真・PR区分は保つ）。上限や障害のときは手動コピペで続けられる
  - 中のスライドの素材画像は、スライドごとに「絵を作る」（REQ-005 の画像生成）か「画像を差し替え」で入れる。写真風の素材画像を含む投稿には AI生成の表示が付く
  - 公開用キャプションは PR表記 → キャプション → AI生成の表示 → キャプションの定型 → ハッシュタグ（固定＋追加）の順に組み立てる
  - 最後のスライドの過去の投稿2件は、承認した時点の公開済みの投稿から選ぶ
  - 承認後に定期処理（tick）がスライドを 1080×1350 の JPEG に画像化する。失敗は「画像化の失敗」（今すぐ再実行でやり直せる）
  - 管理者の画面: 背景写真（30枚まで・使わないにしても消さない）、投稿の型の設定（帯の文言・表紙の対象の候補・最後のスライドの定型文・アカウントの紹介・キャプションの定型・固定ハッシュタグ・ロゴ）、プロンプト版
- 写真の投稿（REQ-001・REQ-005）の公開内容・公開経路は変えていない（共通テストケースの完全な期待文字列で確認）

## API 変更
- 追加: `POST /api/drafts`、`POST /api/drafts/{generationId}/revise`、`POST /api/drafts/manual-prompt`、`POST /api/drafts/manual`（後方互換あり。既存の API は変更なし）
- RPC: `save_post_revision`・`approve_post`・`app.adopt_candidate` を拡張（UPLOAD の動きは変更なし）。管理者用 RPC 5本と service role 用 RPC を追加

## データベース
- マイグレーション: `V10__draft_generation.sql`（追記型。新しい表25・ビュー・RLS・Storage のポリシー・プロンプトの初版。既存の表の変更は `post_failures` の失敗区分の CHECK の付け替えだけ）
- 適用の手順: tick を止めたまま、V10 を含むブランチを ref に指定して migrate を起動 → v10 の適用を確認 → main に push → Pages にデプロイ → 投稿の型の設定を入れる → tick を有効に戻す（設計書 REQ-002 6章）
- ロールバック手順: V10 は新しい表と関数の追加が中心。戻すときは画面と API関数を v0.2 の版に戻す（新しい表は使われないだけで、写真の投稿の流れは V10 の有無に依存しない）。DB を戻す必要が出たら、置き換えた3つの関数を V8/V6 の定義に戻すマイグレーションを足す（新しい表は残してよい）

## 既知の問題・次回対応
- 投稿の型の設定の入力に上限が無い（極端に長い定型や多すぎる固定ハッシュタグを入れると、キャプション本文に使える文字数が無くなる）。上限は要件 BR-002-17 に追記してから入れる
- ネタが外部の入力（REQ-003 の PR入稿・大学ニュース）になる前に、プロンプトへの指示の注入の受入基準を REQ-003 に足す
- 端末の一時保存のキーを「団体＋メンバー」に分けたため、リリースの時点で端末に残っていた作成途中の入力は1回だけ引き継がれない
- 写真の投稿の画面（REQ-001）で、承認の依頼に失敗した後に押し直すと投稿が二重にできることがある（AIの下書きの画面は対応済み）。REQ-001 に受入基準を足してから直す
- テンプレート `niijima@1` は本番で初めて承認された時点で凍結し、以後の見た目の変更は `niijima@2` で行う
- 本番での画像化と公開の通しの確認は、Meta・Instagram アプリの準備と tick の再有効化のあとになる
